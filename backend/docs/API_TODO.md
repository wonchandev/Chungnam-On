## P0 구현 메모 (계획 대비 달라진 점)

- 사업주 정보(`Company`)는 `jobs` 가 아니라 `accounts` 앱에 둠 (회원가입과 함께 생성). 평판(온도)은 `User.temperature`, 평가 `Review` 는 `jobs` 앱.
- 태그는 JSON 이 아니라 불리언 컬럼 5개(`beginner_ok`, `with_friend`, `lunch_provided`, `local_preferred`, `night_shift`) — SQLite/Postgres 모두에서 필터 가능.
- 공고 삭제(`DELETE`)는 `cancelled` 로 소프트 삭제. 마감 자동 처리는 `python manage.py close_expired_jobs` (cron 하루 1회 이상) + 목록 조회 시 마감일 지난 공고는 즉시 제외.
- 지도: 클러스터는 격자 방식(줌 레벨 기반). 규모가 커지면 PostGIS 검토. 목록 API 의 거리순 정렬은 없고 `/api/jobs/nearby/` 가 거리순을 제공.
- 채팅 번역 언어는 "방 안에서 내가 쓰는 언어"를 참가자별로 저장 (`PATCH /api/chat/rooms/{id}/translation/`). 메시지는 원문 + `translations{언어: 번역문}` 로 내려가며 클라이언트가 자기 언어를 골라 표시.
- 온라인 상태는 캐시 카운터 기반. 운영(다중 프로세스)에서는 `REDIS_URL` 필수.
- 행정 가이드 콘텐츠(AdminGuide)는 코드에 시드하지 않음 — 법적 정확성이 필요한 내용이라 관리자 페이지에서 등록.
- 시군 행정코드·좌표는 시드 마이그레이션(대략값). 읍·면·동은 미포함.

## P1 구현 메모

- **알림**: `core.Notification` 에 저장. 지원/승인·거절/근무 완료/새 채팅(오프라인 시, 방 단위로 1개만 갱신)/댓글/동행 참여/민원 답변에서 생성. 유저가 `notifications_enabled=false` 면 저장 안 함.
- **신고/차단/블라인드**: `core.Report`, `core.Block`. 차단하면 채팅 생성·전송 불가, 커뮤니티 글/댓글/동행 상호 숨김. 신고 처리는 Django admin 액션으로 대상(공고/글/댓글) `is_hidden` 처리.
- **근무 완료**: 별도 상태값 대신 `Application.checked_in_at / completed_at`. **후기는 근무 완료된 지원만** 작성 가능(P0 규칙에서 변경).
- **추천**: 규칙 기반 점수(희망·거주 지역, 가능 업종, 요일, 초보 가능, 야간 가능, 긴급, 평판). `WorkerProfile` 입력.
- **AI 챗봇**: 행정 가이드 키워드 검색(RAG, 한국어 번역 후 검색) + OpenAI(`OPENAI_MODEL`, 기본 `gpt-4o-mini`). `OPENAI_API_KEY` 없으면 가이드 검색 기반 간이 답변. SSE 스트리밍 지원. 법률 판단/수수료 등은 답하지 않고 공식 창구(하이코리아, 1345)로 안내하도록 시스템 프롬프트 구성.
- **서류 초안**: 템플릿 3종(체류기간 연장 사유서, 재직증명서 요청, 결근 사유서) — 문장 초안이며 공식 서식이 아님.
- **음성/사진 번역**: Google Speech-to-Text / Vision REST(API 키 방식, 번역과 동일 키; 해당 API 사용 설정 필요). 테스트는 mock.
- **커뮤니티 번역**: 글/댓글은 읽는 사람의 언어로 읽을 때 번역(캐시 재사용), 원문은 `original_*` 로 함께 제공.
- **전화 연결 정책**: 해당 공고의 지원이 **승인된 뒤**에만 상대 번호 제공(`GET /api/chat/rooms/{id}/call/`).
- **미구현(P2)**: 챗봇 출처 표기 고도화/피드백/가드레일, 근무 후기↔평판 연동.
