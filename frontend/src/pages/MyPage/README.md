# 마이페이지

`/mypage`는 로그인한 사용자만 접근한다. 계정 아이콘 드롭다운의 마이페이지에서 진입한다. 비회원의 직접 접근은 로그인 페이지로 이동하고 로그인 완료 후 `/mypage`로 돌아온다. 기존 정보 수정 모달은 이 페이지의 프로필 폼으로 대체했다.

## 연결 API

| 기능 | API |
| --- | --- |
| 프로필·온도·지원/관심/공고 집계 | `GET /api/me/summary/` |
| 기본 정보·프로필 사진·설정 | `PATCH /api/auth/me/` (사진은 multipart) |
| 후기·평판 | `GET /api/users/{id}/reputation/` |
| 근로자 이력 조회·수정 | `GET/PATCH /api/me/worker-profile/` |
| 비밀번호 변경 | `PATCH /api/auth/password/` |
| 내 신고 내역·신고 접수 | `GET/POST /api/reports/` |
| 차단 목록·차단·해제 | `GET /api/blocks/`, `POST/DELETE /api/blocks/{user_id}/` |
| 지역·언어·업종 선택지 | `GET /api/regions/?level=sigungu`, `/api/languages/`, `/api/categories/` |
| 신고 대상 공고 검색·대화 상대 선택 | `GET /api/jobs/?q=`, `/api/chat/rooms/` |

## 동작과 범위

- 온도와 후기는 서버가 계산한 값을 조회한다. 임의 온도나 가짜 후기를 넣지 않는다.
- 근로자는 경력·가능 업종·요일·희망 지역·야간 가능 여부를 저장할 수 있다. 사업주에게는 근로자 이력을 표시하지 않고 본인의 공고·지원자 집계를 보여준다.
- 설정은 선호 언어·알림 수신과 비밀번호 변경이다. 선호 언어 저장은 사용자 프로필 설정이며 전체 UI 번역 기능을 추가한 것은 아니다.
- 신고는 실제 공고·대화 상대·채팅방에서 대상을 고른다. ID를 직접 입력하게 하지 않는다. 게시글·댓글·메시지 신고 API는 기존대로 유지되며 이 페이지에서는 위 3종의 대상만 제공한다.
- 기존 백엔드에는 신고 등록만 있었다. 마이페이지를 위해 같은 `/api/reports/`에 본인의 신고 목록 조회와 읽기 전용 표시 라벨을 추가했다. 다른 사용자의 신고·신고자 정보는 반환하지 않으며, 사용자가 처리 상태를 변경할 수 없다.
- 차단할 사람은 본인의 대화 상대에서 선택한다. 차단·해제 전에 확인하고, 신고가 차단을 자동 실행하지는 않는다.
- 페이지를 로드할 때 인증 실패가 발생하면 재로그인 링크를 표시한다. 로그아웃 후에는 페이지가 로그인 화면으로 바뀐다.
- 기존 프로필 인증 정책을 사용한다. 이메일·전화 인증 여부와 사업장 인증 여부는 사용자가 직접 변경할 수 없다.

## 검증

- 변경 파일 ESLint·프로덕션 빌드·기존 프론트 API 테스트.
- 백엔드 계정·평판·신고·차단 API 테스트. 추가 신고 목록 테스트는 본인 데이터 격리, 비회원 거절, 읽기 전용 처리 상태를 확인한다.
